# 기체별 생성 설정과 기록

공통 생성규칙은 루트의 `PROMPT_IMAGE_WORKFLOW.md`와 `IMAGE_UPLOAD_RULES.md`를 따른다. 이 폴더에는 기체별 선택값과 실제 생성 이력을 저장한다.

## 구조

- `index.json`: 정확한 카드 이름 → 폴더 ID. 설정이나 프롬프트 전문을 넣지 않는다.
- `<기체ID>/settings.json`: 최신 외형 선택값, 성별별 추가 지시, 복사 이력.
- `<기체ID>/images.json`: 이 기체의 이미지 파일명 → 실제 제출 원문, 매니페스트, 해시.
- `<기체ID>/runs/<작업일시>/`: 당시 설정, 제출 원문, 보정 원문, 매니페스트를 보존한다.

기체 ID는 `m-` + 정확한 카드 이름 UTF-8의 SHA-256 앞 16자리다. 이미 등록된 ID는 이름이 바뀌어도 유지하고 index의 이름만 확인해 갱신한다. 새 ID 추가 전에 기존 index와 카드 이름을 대조한다. 새 작업 폴더는 `2026-09-11t051200z`처럼 실제 UTC 작업일시로 정한다. 과거 이관 폴더는 기존 이름을 유지하며 모르는 생성일을 만들어 넣지 않는다.

## 새 작업 저장 순서

1. `prompt.html`에서 기체를 선택하고 설정·텍스트 보기를 검토한다.
2. 기본 **기록 내보내기**로 해당 기체만 담은 JSON을 확보한다. 출력의 `card`가 정확한지 확인한 뒤 해당 폴더의 `settings.json`에 저장한다. 새 기체면 index에 이름과 ID를 추가하고 빈 `images.json`도 만든다.
3. 생성하기 전에 새 runs 폴더에 당시 settings 사본과 제출 원문을 저장한다. 이미지 생성 후 실제 참조 관계와 최종 파일 해시를 manifest에 기록한다. 보정하면 원문을 덮지 말고 별도 파일을 추가한다.
4. `images.json`의 해당 이미지에 `card`, `style`, `gender`, `mode`, `sha256`, `prompt`, `manifest`를 연결한다. 경로는 저장소 루트 기준이다. 원문이 없으면 `prompt: null`로 남긴다. `selectedStyle`은 현재 선택값일 뿐 기존 이미지의 화풍 증거가 아니다.
5. 이미지 등록은 기존 `register-images.py` 절차를 따른다. 기체별 기록과 이미지를 함께 업로드하고 main에서 도감 원문 링크를 확인한다.

## 보존과 호환

- `settings.json`은 최신 설정이므로 다음 작업에서 갱신할 수 있다. 완료한 runs의 당시 설정·프롬프트·기록은 덮어쓰지 않는다.
- 다른 기체의 파일은 수정하지 않는다. 이후 생성 작업에서 공용 `toolkit-data.json`과 `data/generation.json`을 매번 갱신하지 않는다.
- 기존 공용 JSON과 `docs/generation/`은 구버전·과거 링크 호환을 위해 유지한다. 생성기와 도감은 해당 기체의 새 파일을 우선 읽고, 새 기록이 없거나 읽지 못하면 기존 기록을 사용한다.
- `전체 기록 내보내기 (호환용)`은 이전 형식이다. 일반적인 새 작업은 기본 단일 기체 내보내기를 사용한다.
- `scripts/migrate-generation.py`는 기존 공개 기록을 처음 복사하는 이관 도구다. 기존 runs·settings·images 파일을 덮지 않는다. 새 작업을 등록하는 도구가 아니며, 재실행으로 최신 설정을 복구하지 않는다.
- 파일을 나눈다고 외부 업로드 승인·접근 제한이 사라지는 것은 아니다. 차단되면 실제로 반영된 파일과 남은 단계를 구분해 보고한다.
